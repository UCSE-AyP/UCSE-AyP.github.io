Contexto de Gestión del Sistema

Sistema de gestión académica en memoria RAM basado en Arreglo de Estructuras (AoS). Implemente los módulos de gestión algorítmica sobre la nómina de alumnos y resuelva la traza manual en la hoja provista.

ESPECIFICACIÓN DEL MODELO: struct Alumno (A definir por el estudiante) Tipos Primitivos Exclusivos

Cada estudiante del padrón universitario está modelado por el struct Alumno. El alumno debe declararlo en el código fuente utilizando exclusivamente tipos de datos primitivos (deduciendo el tipo correspondiente para cada campo según su dominio y rango):

Campo Origen Descripción, Tipo y Regla de Cálculo
legajo Entrada (cin) Entero positivo único (> 0). Clave primaria inmutable.
anioIngreso Entrada (cin) Año de ingreso a la facultad (entero, 2000 ≤ anioIngreso ≤ 2026).
materiasAprobadas Entrada (cin) Cantidad de asignaturas aprobadas en la carrera (entero, ≥ 0).
promedio Entrada (cin) Real con decimales: promedio general de notas (0.00 ≤ promedio ≤ 10.00).
asistencia Entrada (cin) Real con decimales: porcentaje de asistencia registrado (0.0 a 100.0 %).
condicion Calculado Carácter: si promedio ≥ 7.0 y asistencia ≥ 80.0 → 'P' (Promocionado); si promedio ≥ 4.0 y asistencia ≥ 65.0 → 'R' (Regular); caso contrario → 'L' (Libre).
Orden Obligatorio de Miembros en el Struct: Declare los campos del struct respetando estrictamente el mismo orden en que aparecen en la tabla. Esto es indispensable para que la inicialización por lista de llaves { ... } provista en main() compile sin errores de tipos ni desfasaje de columnas.

Arquitectura de Software: Código Base y Alcance de Implementación

La presentación tabular y el menú interactivo están provistos. El estudiante debe declarar el struct, implementar las 6 funciones algorítmicas y la función auxiliar de intercambio en C++, y resolver en papel la traza manual.

Reutilización Modular: Para alcanzar la máxima valoración de modularidad en inserción, modificación y baja, deberá reutilizar la función de búsqueda previamente implementada. Una búsqueda lineal integrada dentro de la función se considerará funcional, pero recibirá una valoración menor en el criterio de modularidad.

1. Búsqueda por Clave Primaria (Lineal)
10%
Búsqueda por Clave Primaria
Retorno de índice de celda o centinela -1, salida temprana inmediata al hallar la clave y const-correctness (solo lectura).
  • Entrada: Arreglo de solo lectura (const Alumno arr[]), tamaño lógico tam y legajo buscado.
  • Proceso: Recorrido secuencial con salida temprana inmediata al hallar la coincidencia.
  • Retorno: Índice de la celda encontrada (0 .. tam-1) o -1 como centinela de no existencia.
2. Alta / Inserción en Posición (Right-Shift)
15%
Alta con Unicidad de Clave
Control de capacidad (tam < CAPACIDAD), validación de posición (0..tam), verificación recomendada de no-duplicado reutilizando búsqueda y tam++.
  • Entrada: Arreglo Alumno arr[], tamaño por referencia int &tam, posición pos y nuevo registro nuevo (con condición ya calculada en el switch).
  • Validaciones: Rechazar (retornar false) si tam >= CAPACIDAD, si pos < 0 o pos > tam, o si el legajo ya existe en la nómina.
  • Proceso: Desplazar celdas a la derecha (Right-Shift) desde pos, insertar el registro e incrementar tam++.
  • Retorno: true si se insertó con éxito; false si fue rechazada.
3. Modificación in-place (PK Inmutable)
10%
Modificación con PK Inmutable
Reutilización modular recomendada de búsqueda para ubicar el índice, mutación in-place en memoria y clave primaria estrictamente inmutable.
  • Entrada: Arreglo Alumno arr[], tam, legajo a modificar y nuevos datos (materiasAprobadas, promedio, asistencia).
  • Proceso: Localizar registro. Si existe, actualizar in-place materiasAprobadas, promedio y asistencia, recalcular condicion, preservando intactos legajo y anioIngreso.
  • Retorno: true si la modificación fue exitosa; false si el legajo no fue hallado.
4. Baja Física con Compactación (Left-Shift)
15%
Baja Física con Compactación del Arreglo
Reutilización modular recomendada de búsqueda, corrimiento contiguo a la izquierda Left-Shift (cubrir hueco) y decremento tam--.
  • Entrada: Arreglo Alumno arr[], tamaño por referencia int &tam y legajo a eliminar.
  • Proceso: Localizar registro. Si existe, compactar la nómina desplazando los elementos posteriores una posición a la izquierda (Left-Shift) y decrementar tam--.
  • Retorno: true si se eliminó y compactó; false si el registro no existe.
5. Ordenamiento Burbuja Mejorada
15%
Intercambio Completo de Estructuras
Burbuja Mejorada con bandera de corte comparando campo promedio e intercambiando la estructura completa mediante una función auxiliar.
  • Entrada: Arreglo Alumno arr[] y tamaño lógico tam.
  • Proceso: Ordenar en forma DESCENDENTE por promedio mediante Burbuja Mejorada con corte por bandera (huboIntercambio). Intercambiar las estructuras completas mediante una función modular auxiliar intercambiar(Alumno &a, Alumno &b).
  • Retorno: void (modificación in-place sobre el arreglo).
6. Cálculo de Promedio (Estadística)
10%
Cálculo Estadístico
Recorrido acumulador sobre registros válidos, const-correctness (solo lectura) y guarda defensiva tam ≤ 0 retornando 0.0.
  • Entrada: Arreglo de solo lectura (const Alumno arr[]) y tamaño lógico tam.
  • Proceso: Si tam ≤ 0 retornar inmediatamente 0.0 (guarda defensiva ante división por cero). Caso contrario, acumular promedio de las celdas activas y promediar.
  • Retorno: Promedio académico general con precisión decimal (double).
7. Instancia Escrita: Traza de Ordenamiento
25%
Traza Manual en Hoja Impresa
Resolución paso a paso en hoja de examen indicando comparaciones, desplazamientos y prefijo consolidado.
  • Consigna: En la hoja impresa A4, aplique Inserción Directa (Insertion Sort) para ordenar en forma DESCENDENTE el vector V = [38, 14, 62, 8, 27].
  • Detalle requerido: Detallar en cada una de las 4 pasadas: el elemento aux extraído, las comparaciones contra el prefijo ordenado, los desplazamientos a la derecha y el estado resultante del vector.

void mostrarFicha(const Alumno &e) {
    cout << "  +------------------------------------------------------------------+\n";

void mostrarTabla(const Alumno arr[], int tam) {
    if (tam == 0) {
        cout << "  [!] El padron academico esta vacio (tam = 0).\n";
        return;
    }

    cout << "\n+-----+--------+----------+------+----------+--------+-----+--------------+\n";
    cout << "| POS | LEGAJO | ANIO ING | MATS | PROMEDIO | ASIST% | CND | CONDICION    |\n";
    cout << "+-----+--------+----------+------+----------+--------+-----+--------------+\n";

    cout << right;
    for (int i = 0; i < tam; ++i) {
        cout << "| [" << setw(1) << i << "] | "
             << setw(6) << arr[i].legajo << " |   "
             << setw(6) << arr[i].anioIngreso << " |  "
             << setw(3) << arr[i].materiasAprobadas << " |    "
             << setw(5) << fixed << setprecision(2) << arr[i].promedio << " |  "
             << setw(4) << fixed << setprecision(1) << arr[i].asistencia << "% |  "
             << arr[i].condicion << "  | "
             << left << setw(12) << (arr[i].condicion == 'P' ? "Promocionado" : (arr[i].condicion == 'R' ? "Regular" : "Libre")) << right << " |\n";
    }
    cout << "+-----+--------+----------+------+----------+--------+-----+--------------+\n";
    cout << "Total alumnos en padron: " << tam << ".\n";
}

CONDICIONES FORMALES DE DESARROLLO Y EVALUACIÓN

  • Modalidad Bimodal: 75% Laboratorio de Programación (C++) + 25% Instancia Escrita (Lápiz y Papel).
  • Entorno de Desarrollo: El código deberá compilar bajo el estándar C++17 (en Code::Blocks, VS Code, CLion, MinGW / GCC).
  • Estructura de Datos: Se debe utilizar exclusivamente arreglo de estructuras (struct + array AoS). Prohibido vectores paralelos.
  • Capa de presentación preimplementada: El menú y las funciones de presentación tabular están provistos. El estudiante deberá completar en el switch la lectura y validación de datos, las llamadas a las funciones algorítmicas y los mensajes correspondientes. Las validaciones de dominio de los datos ingresados se realizarán en el switch. Las funciones algorítmicas deberán efectuar las validaciones estructurales que les correspondan, como capacidad, posición, existencia o unicidad de la clave.
  • Criterio de Aprobación: El programa debe compilar sin errores bajo C++17. Las advertencias que evidencien problemas funcionales, conversiones inseguras o variables sin inicializar podrán considerarse dentro del bloque afectado; la hoja escrita debe entregarse al finalizar.
